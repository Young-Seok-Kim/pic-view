# 미션 구조 개편 계획

> 장소별 미션과 전체 미션을 나누고, "방문 인증"에서 "장면 기록"으로 옮깁니다.
> 작업을 쪼개 단계마다 커밋합니다. 이 문서는 진행하며 갱신합니다.

작성 : 2026-08-16 · 브랜치 `feat/pose-guide-and-ui-fixes`

---

## 왜 바꾸나

지금 미션은 **"몇 곳을 다녀왔는가"** 를 셉니다. `다녀왔어요` 버튼을 누르면
방문 기록이 쌓이고, 미션은 그 개수를 셀 뿐입니다.

그런데 이 앱의 차별점은 장소를 방문했다는 사실이 아니라 **어떤 빛에서,
어떤 방향으로, 어떤 구도로 장면을 남겼는가** 입니다. 방문 수를 세는 미션은
어느 관광 앱에나 있고, 이 앱이 계산해 온 빛 데이터를 하나도 쓰지 않습니다.

| 기존 | 개선 |
|---|---|
| 배지 0 / 6개 | 장면 6 / 24 |
| 다녀왔어요 | 빛을 발견했어요 |
| 장소 방문 | 촬영 조건 달성 |
| 단순 누적 | 관찰 · 비교 · 기록 |

---

## 두 화면은 서로 다른 일을 한다

|  | 장소별 미션 | 전체 미션 모음 |
|---|---|---|
| 사용자의 물음 | 여기서 지금 무엇을 하지? | 다음에는 무엇을 해볼까? |
| 기준 | 장소 · 현재 빛 · 날씨 | 유형 · 계절 · 누적 진행 |
| 노출 수 | 지금 조건에 맞는 2~3개 | 전체 + 유형 필터 |
| CTA | 촬영 시작 · 일정 저장 | 미션 상세 · 추천 장소 보기 |
| 완료 반영 | 현장에서 즉시 | 전체 진행률에 자동 |

같은 `missionId` 를 공유해 한쪽에서 채우면 다른 쪽이 함께 갱신됩니다.

## 미션 유형과 아이콘

| 유형 | 아이콘 | 색 | 의미 | 완료 문구 |
|---|---|---|---|---|
| 빛 | ☼ | 머스터드 | 황금시간 · 빛 방향 · 구도 | 빛을 발견했어요 |
| 날씨 | ☁ | 블루그레이 | 흐림 · 비 · 눈 · 시정 | 색을 기록했어요 |
| 계절 | ✿ | 핑크 | 계절의 색 · 식생 · 변화 | 계절을 관찰했어요 |
| 장소 | ⌖ | 세이지 | 정읍 명소 · 장소 이동 | 장면을 발견했어요 |
| 비교 | ⇄ | 브라운 | 시간대 · 장소 · 구도 비교 | 차이를 비교했어요 |
| 기록 | ✎ | 라벤더 | 사진 설명 · 감상 · 엽서 | 정읍을 완성했어요 |
| 공유 | ↗ | 피치 | 큐레이션 · 공유 · 추천 | 오늘의 정읍을 소개했어요 |

아이콘은 미션 종류를 **보조**할 뿐이라 항상 글자와 함께 씁니다.
미완료는 채도를 낮춘 원형 바탕, 선택은 테라코타 테두리 + 크림 바탕,
완료는 같은 아이콘에 체크를 더합니다.

## 판정에 쓸 수 있는 데이터

미션 조건은 **실제로 판정할 수 있는 것만** 씁니다. 화면에 조건을 적어 놓고
영원히 안 채워지는 미션은 없느니만 못합니다.

`VisitLogEntity` 에 이미 쌓이는 값:

| 필드 | 쓸 수 있는 조건 |
|---|---|
| `phaseName` | 골든아워 · 블루아워 · 아침 · 저녁 구분 |
| `score` | 포토스코어 N점 이상 |
| `photoUri` | **직접 찍은 사진이 있는가** (방문만 한 것과 구분) |
| `visitedAt` | 계절 · 시간대 · 같은 날 여부 |
| `contentId` `title` | 장소 지정 · 서로 다른 장소 수 |

> **못 하는 것**: 사진 내용 분석(반사·그림자·색). 그래서 "물에 비친 정읍"
> 같은 미션은 *피사체* 가 아니라 **장소**(연못·저수지·수변)로 조건을 잡습니다.
> 사진을 판독한 척하지 않습니다.

## 실시간 연동

두 화면은 **같은 Room Flow**(`DiaryRepository.observeDays()`)를 구독합니다.
방문 기록이 하나 쌓이면 장소별 미션과 전체 미션이 **동시에** 다시 계산돼
따로 맞출 것이 없습니다. 참고 자료의 `MissionSyncStore`(localStorage +
BroadcastChannel)가 웹에서 하던 일을 Room 이 그대로 합니다.

| 참고 자료(웹) | 이 앱(안드로이드) |
|---|---|
| `missionSync.getProgress(id)` | `Missions.progress(visits)` |
| `getPlaceMissions(placeId)` | `Missions.forPlace(title, visits, phase)` |
| `completeEvidence(id, photoId)` | 방문 기록에 `photoUri` 저장 |
| `BroadcastChannel` 로 탭 간 전파 | Room `Flow` 가 구독 중인 화면에 전파 |
| 같은 증거 ID 중복 방지 | `distinctBy { contentId }` · `coerceAtMost(target)` |

증거가 따로 없습니다. **사진이 곧 증거**입니다. 별도 완료 테이블을 두지
않으므로 "완료 처리를 깜빡해서 배지가 안 나오는" 버그가 원천적으로
없고, 사진을 지우면 진행도도 정직하게 되돌아갑니다.

---

## 하지 않기로 한 것

**사진 내용 판독.** 반사·그림자·색을 사진에서 읽어 내려면 온디바이스 모델이
필요하고, 잘못 판정하면 "찍었는데 인정 안 됨"이 되어 미션 자체를 불신하게
됩니다. 조건을 장소·시각·점수로 바꿔 잡습니다.

**방문만으로 완료.** `다녀왔어요` 만 눌러도 채워지던 것을, 사진이 있어야
채워지도록 바꿉니다. 다만 기존 방문 기록을 무효로 만들지는 않습니다.
