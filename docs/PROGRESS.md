## 환경

| 항목 | 값 |
|---|---|
| 프로젝트 | `C:\dev\pic-view` |
| SDK | `C:\Users\rmawn\AppData\Local\Android\Sdk` (Android Studio 동봉본) |
| 에뮬레이터 | MEmu · adb `127.0.0.1:21503` (무무 아님) |
| 실행 | `D:\Program Files\Microvirt\MEmu\MEmu.exe` |

**에뮬레이터 시계 주의.** MEmu 는 재부팅하면 CST 로 되돌아갑니다. 그러면 앱이
미래 시각의 기상 실황을 요청해 기상청이 빈 응답(65바이트)을 주고, 기온이 `—`
로 표시됩니다. 앱 버그가 아니므로 시계를 맞추면 됩니다.

```bash
"$ANDROID_HOME/platform-tools/adb.exe" -s 127.0.0.1:21503 shell "date $(date +%m%d%H%M%Y.%S)"
```

**설치 주의.** 스트리밍 설치가 이 에뮬레이터에서 NPE 로 실패합니다.
`adb install -r --no-streaming` 을 쓰세요.

## 완료

### 버그 수정
- **상단 인셋이 전 화면에서 미적용** — `requestApplyInsets` 호출이 없어 탭으로
  뒤늦게 붙는 프래그먼트가 인셋 최초 배포를 놓쳤습니다. `util/Insets.kt` 로
  모아 10개 화면에 적용. 패딩은 대입이 아니라 **가산**이라 XML 여백이 보존됩니다.
- **홈 기온 칸에 "촬영지"가 표시** — 화면 문구를 `substringAfterLast` 로 잘라
  기온을 뽑고 있었습니다. 관측값이 없으면 문구가 "정읍의 촬영지"가 되며 마지막
  낱말이 그대로 박혔습니다. `MainViewModel.temperatureC` 로 숫자를 분리.
- **탐색 탭 칩이 상태바에 겹침** — 이 화면만 인셋 처리가 빠져 있었습니다.
- **다이얼로그가 기본 모양** — AppCompat `AlertDialog` 라 테마가 안 먹었습니다.
  `MaterialAlertDialogBuilder` + M3 다이얼로그 테마로 교체.
- **`LightPhase.shortLabel` 추가** — "일출 골든아워"가 3분할 카드에서 잘렸습니다.

### 포즈 가이드 (신규)
촬영 화면이 구도선 3개만 그어 주고 끝나 "사진 찍는 앱"이라는 정체성이
약했습니다. 카메라를 든 순간 실제로 막히는 건 구도가 아니라 "그래서 어떻게
서지"입니다.

- `domain/pose/Pose.kt` — 포즈 6종(뒤돌아 걷기·점프샷·실루엣·앉아서 감상·
  하늘 향해·손 프레임)
- `domain/pose/PoseRecommender.kt` — **점수를 고정하지 않고** 지금의 빛
  (`LightPhase`) · 장소 방위(`Facing`) · 인원(`GroupSize`)으로 매번 계산.

  고정값이면 한밤중에도 실루엣이 1등으로 뜹니다. 실루엣은 해를 등져야
  성립하므로 그때는 후순위가 맞습니다. **실제로 야간엔 뒤로 밀리고 일몰
  골든아워엔 100점 1위로 올라오는 것을 확인했습니다.**
- 카드는 알약 모양 가로 배치. 세로로 쌓았더니 화면 높이를 넘겨 잘렸습니다.

### 코스 입력 보강
시안에 있던 항목이 앱에 없어 "오늘 지금부터"만 짤 수 있었습니다.

- **여행 날짜** — 고른 날짜의 일출·일몰을 천문 API(`locdate`)로 다시 받습니다.
  오늘 값 재사용은 안 됩니다. 정읍 일몰은 8월 19:26, 12월 17:21 로 두 시간
  넘게 차이 나서 골든아워 슬롯이 통째로 어긋납니다. **12/16 선택 시 07:35 /
  17:21 로 바뀌는 것을 확인했습니다.**
  오늘이 아니면 "지난 시각은 지금으로 당긴다" 규칙도 꺼야 합니다. 밤에 내일
  일출 코스를 짜면 시작이 22시로 밀립니다.
- **인원 구성**(혼자·커플·가족·친구) — 배치 규칙은 그대로 두고 체류 시간에만
  배수(1.0/1.1/1.35/1.25)를 곱합니다. 여럿이면 한 곳에 오래 머물러 도는 곳이
  줄어드는 것이 실제와 맞습니다.
- **스타일 태그 8종**으로 확장, 표기를 `#` 로 통일.
- **이동수단에 KTX+렌트** 추가(시내 이동 계산은 자가용과 동일).

  문서 느낌이 강해 앱과 겉돌았습니다.

- 본문에는 디스플레이 서체를 쓰지 않습니다. 큰 글씨 모드에서 오히려
  읽기 어려워집니다.

### 나중에 할 것 (사용자 요청, 재료 대기 중)

**1. 첫 실행 온보딩 슬라이더 + 기능 안내 코치마크**

앱을 처음 받았을 때 흔히 보는 흐름입니다.

1. 애니메이션/사진이 뜨고
2. 좌우로 넘기며 앱 기능을 설명하고
3. 그다음 게임처럼 **화면 위에 말풍선을 띄워 "여기를 눌러보세요"** 로 유도

> **막힌 이유**: 슬라이더에 넣을 사진을 아직 다 준비하지 못했습니다.
> 사진이 준비되면 진행합니다. 사용자가 잊고 있으면 알려 주기로 했습니다.

현재 `OnboardingActivity` 가 있지만 텍스트 3장짜리이고, 코치마크는 없습니다.

**2. 온보딩 다시 보기 버튼**

처음에는 대개 건너뛰는데, 나중에 다시 보고 싶어도 방법이 없습니다.
MY 탭에 "앱 사용법 다시 보기"를 넣어 온보딩을 다시 띄울 수 있게 합니다.

**3. README 정비 (캡처 포함)**

지금 README 는 빌드 방법 위주입니다. 화면 캡처를 넣고 기획 의도·기능별
상세 동작을 적습니다. 위 밀린 작업이 끝난 뒤에 진행합니다.

### 하지 않기로 한 것

**코스 입력의 예산 슬라이더.** 시안에는 "1인 예산 3~20만원" 슬라이더가
있지만, 관광공사 `detailIntro2` 의 요금 필드를 정읍 실데이터로 확인한 결과
금액 숫자가 없습니다.

| 장소 | `usefee` |
|---|---|
| 구파백정기의사기념관 | `무료` |
| 정읍사예술회관 | `공연, 전시에 따라 다름` |
| 정읍문화원 | (비어 있음) |

음식점 `firstmenu` 도 `단풍미락정식` 처럼 메뉴명뿐입니다. 네이버 지역검색
API 도 상호·주소·전화만 주고 가격이 없습니다. 슬라이더를 두면 값을 옮겨도
코스가 바뀌지 않는 장식이 됩니다. 대신 **입장료를 상세에 표시**하는 쪽으로
바꿨습니다(미완료 9번).

**"무료 입장 위주" 코스 토글.** 무료 여부로 거르려면 후보 85곳 전부에
`detailIntro2` 를 호출해야 해 현실적이지 않습니다.

## 시안과의 관계

Figma 파일에는 두 세대가 섞여 있습니다.

- **구세대** (프레임 `2:2`~`14:2`) — 정읍 여행, 스탬프 수집, 포토 프레임,
  O2O, 색감 필터
- **신세대** (프레임 `26:2`~`34:2`) — `🏠 HomeScreen`, `🗺️ CourseInputScreen`
  등 이모지 접두사

앱은 신세대만 부분 구현했습니다. 화면마다 정보 밀도와 컴포넌트 스타일이
안 맞아 보이는 원인이 여기에 있습니다.

## 검증 방법

```bash
# 단위 테스트 30개 (빛 계산 · 코스 배치 규칙 · 미션 판정 · 계절 D-day)
./gradlew testDebugUnitTest

# 빌드 → 설치 → 실행
./gradlew assembleDebug
adb -s 127.0.0.1:21503 install -r --no-streaming app/build/outputs/apk/debug/app-debug.apk
adb -s 127.0.0.1:21503 shell am start -n com.youngs.picview/.MainActivity
```

**화면 확인은 `adb exec-out screencap` 이 안 됩니다.** MEmu 의 GPU 렌더링
특성상 흰 화면만 나옵니다. `uiautomator dump` 로 텍스트·좌표를 읽거나
데스크톱 스크린샷을 쓰세요.

```bash
adb -s 127.0.0.1:21503 shell uiautomator dump /sdcard/ui.xml
adb -s 127.0.0.1:21503 shell cat /sdcard/ui.xml > ui.xml
```

> Git Bash 에서는 `/sdcard` 경로가 윈도우 경로로 바뀝니다.
> `MSYS_NO_PATHCONV=1` 을 앞에 붙이세요.
